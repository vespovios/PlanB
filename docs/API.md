# PlanB API and MCP reference

The browser, the REST API and the MCP adapter all call the same server functions. Every change goes through the same validation (`src/shared/model.ts`, `src/shared/ops.ts`, `src/shared/storyboard.ts`) and the same revision check.

## Authentication

- **Browser:** `POST /api/auth/login` sets an `HttpOnly` session cookie. Writes with a cookie must also send the header `x-planb-csrf: 1`.
- **Agent:** `Authorization: Bearer planb_…`, a token created in Settings. Agent tokens can use every episode, asset, export and MCP endpoint, but not `/api/tokens` or password changes.
- Another account's resources return `404`, the same as missing ones.

## Revision rules

1. Read the episode. The response includes `revision`.
2. Send changes with `baseRevision` equal to that revision.
3. If someone saved in between, the server answers **409**:
   ```json
   { "error": "Stale revision: …", "code": "stale_revision", "currentRevision": 12, "baseRevision": 10,
     "newerRevisions": [{ "revision": 11, "authorLabel": "Peter", "summary": "Edited \"Packing\" title" }, …] }
   ```
   Read again and reapply only the intended change. There is no force flag.
4. A batch is atomic. Either all of its operations apply as **one** new revision, or none do.

Fields you don't mention are never changed. A text-only scene change does not touch its shots, references or storyboard.

## REST endpoints

| Method & path | Purpose |
| --- | --- |
| `GET /api/episodes` | List episodes (id, title, status, revision, scene count, totals) |
| `POST /api/episodes` `{title, brief?, withExample?}` | Create an episode (`withExample` adds the illustrative opening) |
| `GET /api/episodes/:id` | Full episode document with `revision` |
| `GET /api/episodes/:id/agent-view` | Same, with scene start times and storyboard summaries instead of drawing objects |
| `POST /api/episodes/:id/changes` `{baseRevision, summary?, operations[]}` | Apply a batch (see below). Returns `{episode, created}`, where `created` maps operation index → new ID. |
| `GET /api/episodes/:id/revisions` | Revision history (author, summary, time) |
| `GET /api/episodes/:id/revisions/:rev` | Snapshot of one revision |
| `POST /api/episodes/:id/restore` `{targetRevision, baseRevision, acknowledgeLaterRevisions?}` | Restore an earlier version as a new revision. If more than one revision would be reverted, returns 409 `later_revisions` with the list until acknowledged. |
| `GET /api/episodes/:id/checklist[?order=story\|filming\|location&format=markdown]` | Filming checklist (`groupByLocation=1` still works) |
| `GET /api/episodes/:id/export.zip` | Portable plan bundle ([PLAN-FORMAT.md](PLAN-FORMAT.md)) |
| `POST /api/episodes/:id/assets` (multipart `file`) | Upload a PNG/JPEG (≤10 MiB). Returns `{asset: {id, mime, bytes, width, height}}`; attach it with `addImage`. |
| `GET /api/assets/:assetId[?w=320]` | Image binary (original, or a cached WebP thumbnail). Owner only. |
| `GET /api/storyboard-schema` | Storyboard JSON schema, guidance and example |
| `GET /api/episodes/:id/events` | Server-sent events: `revision` whenever a new revision is saved |
| `DELETE /api/episodes/:id` | Soft-delete an episode (browser session only) |
| `GET/POST/DELETE /api/tokens[/:id]` | Manage agent tokens (browser session only) |

### Change operations

Each operation is an object with an `op` field. IDs are generated by the server unless you supply a well-formed one (`sc_…`, `sh_…`, `at_…`) to refer to a new item later in the same batch.

| op | Fields |
| --- | --- |
| `updateEpisode` | `fields: {title?, brief?, outline?, notes?, targetSeconds?, status?}` |
| `addScene` | `scene: {title, durationSeconds, status?, description?, purpose?, notes?, voiceover?, audio?, location?, shots?: [{description, framing?, cameraNotes?, priority?, outcome?}]}`, `index?`, `id?` |
| `updateScene` | `sceneId`, `fields: {title?, durationSeconds?, status?, description?, purpose?, notes?, voiceover?, audio?, location?, thumbnailAttachmentId?, cutToNext?, filmDay?, filmStop?}` |
| `deleteScene` / `restoreDeletedScene` | `sceneId` (+ `index?` for restore; the scene comes back from history with its shots, references and drawing) |
| `moveScene` | `sceneId`, `index` (0-based target position) |
| `addShot` | `sceneId`, `shot: {description, framing?, size?, angle?, movement?, cameraNotes?, gear?, priority?, outcome?, skipReason?, journalRefs?}`, `index?`, `id?` (`gear` = kit-list IDs) |
| `updateShot` / `deleteShot` / `moveShot` | `sceneId`, `shotId` (+ `fields` / `index`) |
| `addLink` | `sceneId`, `label`, `url` (http/https), `caption?` |
| `addImage` | `sceneId`, `assetId` (uploaded to this episode), `label?`, `caption?` |
| `updateAttachment` | `sceneId`, `attachmentId`, `fields: {label?, caption?, url?}` |
| `removeAttachment` | `sceneId`, `attachmentId`. Refused while the image is the storyboard background; detach it with `saveStoryboard` in the same batch. |
| `saveStoryboard` | `sceneId`, `storyboard: {width?, height?, backgroundAttachmentId?, description?, objects[]}`. Replaces the whole document; the server renders the PNG preview in the same revision. |
| `deleteStoryboard` | `sceneId` |
| `addGear` | `item: {name, kind?, notes?}`, `id?`; kind is `camera lens support audio light power storage other` |
| `updateGear` / `removeGear` | `gearId` (+ `fields: {name?, kind?, notes?}`); removing an item also removes it from shots |

Scene fields: `durationSeconds` is planned **screen** time in whole seconds. `status` (`draft`/`ready`) is the creator's planning status; it is independent of episode status and of captured shots. `purpose` answers "what should the viewer understand or feel?". `description` is visible action. `voiceover` holds VO intent or text, and `audio` holds audio/music intent; these are separate fields. Shot `outcome` is `open` (nothing recorded yet), `filmed` (the creator reports filming it, **not** that the footage has been reviewed) or `skipped` (deliberately dropped: resolved, but no footage exists). `skipReason` (≤160 characters) is kept only while skipped. `journalRefs` (up to 20 Trip Log entry IDs or URLs) links shots to the trip journal. `outcomeAt` is stamped by the server when the outcome changes. The legacy boolean `captured` mirrors `outcome === "filmed"` and is still accepted on writes (true → filmed, false → open). Shot `size` (`ews ws fs mws ms mcu cu ecu ins`), `angle` (`eye high low ground overhead aerial pov ots dutch`) and `movement` (`static pan tilt push pull track handheld zoom aerial whip`) are optional; scene `cutToNext` (`cut match action jcut lcut cutaway jump smash cross montage whip dissolve fade`) is an editing intention for the rough cut. `filmDay` and `filmStop` (whole numbers 1–99, or `null`) say when a scene gets filmed (shooting day, then stop within the day); they never change story order, and the checklist's `filming` order uses them. Definitions: `src/shared/vocab.ts`, or the MCP tool `get_shot_and_cut_guide`.

Example (curl):

```bash
TOKEN=planb_…; EP=ep_…
curl -s https://planb.example.com/api/episodes/$EP -H "Authorization: Bearer $TOKEN" | jq .episode.revision
curl -s -X POST https://planb.example.com/api/episodes/$EP/changes \
  -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"baseRevision": 7, "summary": "Add reaction shot",
       "operations": [{"op": "addShot", "sceneId": "sc_…", "shot": {"description": "Reaction as the bike clears the ramp", "framing": "Close-up", "priority": "optional"}}]}'
```

## MCP tools

Endpoint: `POST /mcp` (Streamable HTTP, stateless, JSON responses), with `Authorization: Bearer <agent token>`. Server instructions summarise the save rules.

| Tool | Does |
| --- | --- |
| `list_episodes` | List episodes |
| `get_episode` | Read the latest saved episode (revision, brief, outline, notes, scenes with every field, shots, references, storyboard summaries) |
| `create_episode` | New episode (optionally with the example opening) |
| `apply_changes` | `{episodeId, baseRevision, summary?, operations[]}`: the operations above, as one revision |
| `get_filming_checklist` | Checklist (Markdown): `order` = story, filming (day/stop) or location |
| `list_revisions` / `restore_revision` | History and undo/restore with explicit acknowledgement |
| `get_storyboard_schema` / `get_storyboard` | Drawing schema and a scene's full editable drawing |
| `get_image` | Image or preview as MCP image content (binary, separate from text reads) |
| `upload_image` | Store a user-supplied base64 PNG/JPEG; then `addImage` |
| `get_shot_and_cut_guide` | Shot size / angle / movement and cut-type vocabulary with definitions and when to use them |
| `get_workflow_guide` | The agent workflow ([AGENT-WORKFLOW.md](AGENT-WORKFLOW.md)) |
